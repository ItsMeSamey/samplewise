# Reproducible numerical evidence

Run `npm run benchmark` from the project root. The full generated inputs, allocations, objective values, sensitivity examples and timings are in [results.json](../benchmarks/results.json). The suite uses 48 synthetic field-planning cases generated by a recorded 32-bit LCG with seed 20261029; it is not a real survey dataset or a representative sample of all possible studies.

Every case has 3-6 strata, populations 100-2,500, SD 5-70, sample cost 2-20 credits, minimum sample 3-12, maximum sample 50-180 clipped at population, and budget equal to mandatory cost plus 250-1,200 credits. The generator and full inputs are included so the scope is inspectable.

| Comparison: exact vs baseline | Median variance reduction | Mean | Maximum |
| --- | ---: | ---: | ---: |
| Cost-aware marginal-gain greedy | 0.0478% | 0.1162% | 0.9882% |
| Balanced sample counts | 24.6863% | 28.5142% | 70.0047% |

The exact method strictly improved over greedy in 31 of 48 cases and tied in 17, using a 1e-8 percentage-point threshold. Greedy is already strong on this generated distribution. Samplewise provides an optimal integer answer within explicit constraints, reproducible comparisons and sensitivity checks.

| Synthetic example | Exact allocation, input order | Exact variance | Reduction vs greedy | Reduction vs balanced |
| --- | --- | ---: | ---: | ---: |
| CreekWatch | 53, 46, 6, 8 | 3.454149703 | 0.0661% | 50.2200% |
| CampusPulse | 23, 96, 20, 23 | 3.109612760 | 0% | 40.4036% |
| Small-budget greedy trap | 2, 3 | 30.665833333 | 9.2481% | 9.2481% |

The tiny greedy trap is a deliberately selected counterexample, not typical performance. The example has two equal populations of 100, SDs 11 and 14, costs 3 and 5, sample bounds 1-8 and budget 21. Greedy takes [3,2], spends 19 and achieves variance 33.790833333. The exact allocation [2,3] spends 21. This exposes the indivisibility of unequal costs rather than an advantage from different budget caps.

The recorded run used Node v26.11.1 on Linux x64. Solver-only median time was 0.569 ms and maximum 25.884 ms after one warm-up; peak process RSS was 65.13 MiB. A 12-stratum stress case with a 17,174,400-transition upper bound took 176.45 ms for the main solve plus two sensitivity re-optimizations. These are machine-dependent Node timings, not measured browser latency. No paid compute, GPU or external API was used. Subsequent regenerations will change timestamps and timings.

Correctness evidence is separate from speed evidence: `npm test` includes 1,800 seeded exhaustive integer-allocation scenarios across two independently authored test suites, actual-sample enumeration for the variance formula, and input/export edge cases. The critic suite alone checks 21,108 exact and frontier plans. See [METHOD.md](METHOD.md) and the included test source. The separately tasked critic was an AI agent; this was not a human statistical audit.

All reductions are in the model's variance. They are not measured reductions in real-world error, field cost, bias or nonresponse. Pilot estimates, frame quality and collection design still determine whether the model is appropriate.
